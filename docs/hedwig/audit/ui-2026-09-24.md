# Hedwig v2 reader and type: UI audit (2026-09-24)

This is a read-only audit. Paths are relative to `frontend/src` unless they start with `backend/`. The baseline is green: `node --test src/hedwig/v2/*.test.js src/hedwig/theme/tokens.test.js` passes 114 of 114 on Node 22.23.

## 1. HTML body path

**Route.** `backend/src/routes/mail.js:373` returns `{ html, text, attachments, hasBlockedRemoteImages, senderEmail, senderName }` (see :449 and the IMAP branch at about :488).
- **No `trackersBlocked`.** Only the mock sets it, so in production Thread.jsx:342 only ever says "Remote images blocked".
- **Sanitised on the server** (`emailSanitizer.js`, `stripEmailHead` at :405).
- **Remote images** are blocked when the response is built and never written back to the cache (:440-448). `?remoteImages=1` skips the blocking. The client call is `api.getMessageBody(id, remoteImages)` (`utils/api.js:104`), which merges duplicate in-flight requests.
- **cid images** become `data:` URIs on the server (`imapManager.js:5413`), and inline images are left out of `attachments` (:837-846).

**MessagePane** (`components/MessagePane.jsx`)
- Fetch at :435-513, with a 50-entry cache and a retry.
- `handleLoadImages` (:1427) marks the id in `imagesRequestedRef`, evicts the cache entry and bumps `retryKey`, which refetches with `remoteImages=true`. Allow sender and Allow domain use `api.addToImageWhitelist({type, value})`. The banner is at :2481.

**MessageBodyView** (`components/MessageBodyView.jsx`)
- **srcDoc** (:305-340):
  - CSP `script-src 'none'` and `<base target=_blank>`.
  - `rel=noopener` on every `<a>`.

It is a separate document, so it reads no upstream or `--hw-*` variables. Under hedwig-night it is a white page; put it on a deliberate white card.

## 2. Quoted history

- **Upstream frontend has no HTML quote detection.** It only styles `blockquote` (MessageBodyView.jsx:339).
- **Hedwig backend `splitHtml`** (`backend/src/hedwig/indexer/parse.js:185`) returns text `{main, quoted, signature}`. It treats as quoted:
  - the classes in `QUOTE_CLASS` (:160): `gmail_quote(_container)`, `x_gmail_quote`, `yahoo_quoted`, `protonmail_quote`, `moz-cite-prefix`, `OutlookMessageHeader`, `zmail_extra`, `replyQuote`;
  - any `<blockquote>` that is not a forward (`FORWARD_START`, :166);
  - `(x_)divRplyFwdMsg`, `appendonsend` and `stopSpelling`, plus everything after them (:163).
- **For the frame:** port these selectors into a `DOMParser` pass in `v2/format.js`, `splitQuotedHtml(html) → {main, quoted}`. Pass `main`, and add a "Show quoted text" toggle that swaps in the full html. Collapse bare `blockquote` only when it has `type="cite"` or the message is a reply: The Ken uses blockquotes for pull quotes.
- **v2 `newTextOf`** (`format.js:198-208`) works line by line:
  - It stops at `^On .+wrote:$` or `^--+ Original Message`.
  - It drops every line starting with `>`.
  - It collapses blank runs.
  - It is English-only, misses two-line Gmail headers and Outlook "From:/Sent:" blocks, and eats `>` lines in newsletters.
- **Why The Ken showed as a paragraph:** `loadBody` (threadData.js:36-40) prefers `b.text`, the text/plain part, over `htmlToPlain(html)`.

## 4. Type system

**How it resolves**
- `fonts.js` `FONT_SETS` sets `--font-sans`, `--font-mono` and `--font-display` through `applyFontSet` (:440), on documentElement.
- `effectiveFontSet` (:467) maps the Hedwig themes plus `'default'` to the `hedwig` set (Instrument Sans, DM Mono, Instrument Serif, :13-15). It is called from `App.jsx:41` and `store/index.js:700,710`.
- `hedwig/theme/tokens.js:106-118`: `--hw-font-display`, `--hw-font-body` and `--hw-font-mono` are `var(--font-*, FONT_STACKS.*)`.
- **`--hw-font-why` is hard-coded to the serif** (:117) and ignores the font set.
- `theme/fontFaces.js:5` is one Google Fonts link, injected unconditionally (`styles.js:145`). Upstream sets self-host (`public/fonts/fonts.css`).
- `V` (`v2/primitives.jsx:25-28`) and `T` (`views/ui.jsx:29-32`) wrap the variables.

**Switching to the system stack in one place**
1. Add a `system` set to `FONT_SETS`: `-apple-system, BlinkMacSystemFont, 'Segoe UI', Roboto, sans-serif` for sans and display, `ui-monospace, SFMono-Regular, Menlo` for mono.
2. Return `'system'` instead of `'hedwig'` in `effectiveFontSet` (:467-469). Upstream sets and the retro pairing are unchanged, and `hedwig` stays pickable.
3. Set `tokens.js:117` to `var(--hw-font-body)`.
4. Gate `ensureHedwigFonts` on the effective set being `hedwig`.
5. Drop the italic in `Why` (primitives.jsx:83), `ui.label` and `ui.why` (styles.js:157,161), and TierNote (:19,31). That covers most of it.

## 6. Layout bug: body text over "Remind me if no reply"

- **Where the text comes from.** "Delivered to … Subscriber to …" appears nowhere in the code or locales. It is The Ken's own text/plain body, rendered by `MessageBlock` (:145-147).
- **Cause: flex shrink, not positioning.**
  - The desktop `<section>` (:491) is a fixed-height `flex-direction:column; overflow-y:auto`.
  - The messages wrapper at **:442** is `{flexGrow:1, minHeight:0}`, so `flex-shrink` stays at 1.
  - Every sibling keeps `min-height:auto`, so this wrapper alone absorbs the overflow.
  - It shrinks below its content, which then overflows visibly. The reply bar (:502) sits at the shrunken bottom, so message text paints over the Remind row and the input.
- **Fix:**
  ```jsx
  // :442
  <div style={{ display:'flex', flexDirection:'column', flexShrink:0 }}>
  // :502
  <div style={{ paddingTop:14, borderTop:`1px solid ${V.line2}`, flexShrink:0 }}>
  ```
  The spacer at :501 still pushes the bar down on short threads, and the same change is safe in the phone scroller (:479). Optionally make the bar `position:sticky; bottom:0` on `V.paper`.
