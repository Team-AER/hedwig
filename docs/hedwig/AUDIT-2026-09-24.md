# Hedwig v2 audit brief, 2026-09-24

The user opened Hedwig and saw the classic upstream shell, no summaries, no AI output, and stale
mail. This brief records what production (uranus LXC 164, https://hedwig.brainfc.uk, commit
4994384) actually did in the 30 hours after the v2 deploy, so the audit works from evidence.

Sources of truth, in order: `docs/hedwig/PRD-v2-product.md`, `docs/hedwig/PRD-ai-rebuild.md`,
`docs/hedwig/V2-BUILD.md` (the build contract), then the code.

### Model runtime: Qwen is unreachable, Gemma does everything

- Every Qwen call in the last 30 h failed: "no response within 45000 ms" (13), "timeout" (10),
  aborted (1). A direct `Say ok` to `Qwen/Qwen3.8-Flash-Next` on llm-proxy took >120 s with no
  answer; vLLM on dgx-spark reports 4 running, 8 waiting (7 "deferred") from other clients.
  Gemma answers `Say ok` in 1.9 s.
- Consequences: every Tier 2 call burns 45 s and a lane slot before falling back; the labels
  judge ran its "reasoning" tier on Gemma (63 calls, tier=reasoning, model=gemma) although the
  design says the two judges must be different models; Ask/agent/summary/insights all show Qwen
  failures then Gemma. Nothing in the UI says Tier 2 is degraded.
- `hedwig_ai_calls` by feature in 30 h: extraction 153, labels 100, summary 46, cards 3,
  sort 3, ask 7, agent 5, insights 3, triage 3. Many rows have empty `lane`/`tier` columns.
- Worker log: `[hedwig] lanes: redis not connected; lane limits apply per process` (cosmetic on
  first use? verify the worker actually connects; REDIS_URL is set).

### Mail sync: INBOX realtime sync fails every tick

- Backend log, every 6 minutes for hours: `Message sync error for p***@yahoo.com/INBOX:
  Connection not available` → treated as a provider refusal → 30 s backoff → `Reconnecting…` →
  `Reconnected` → silence → same failure 6 min later. 21 failures in 6 h, 1 `syncNow complete`
  (manual). The backfill pass every ~40 min is what keeps INBOX in sync, so new mail can lag
  40 minutes and IDLE push never fires.
- Four zlib errors in 12 h (`invalid distance code`, `invalid distance too far back`, `invalid
  literal/length code`) each followed by `IMAP connection closed`: imapflow's COMPRESS=DEFLATE
  stream corrupts on Yahoo. imapflow supports `disableCompression`.
- Earlier packet capture (memory): Yahoo sends FIN exactly 300 s after connect when the client
  sends nothing; imapflow auto-IDLE only starts when a mailbox is SELECTED and the connection is
  not busy (`autoIdleDelay` 3 s here). The health check's "has IDLE enabled but has not been
  idling" warning never fired, so either `client.idling` is true on a dead socket or the connection
  is gone before the streak threshold. `Connection not available` from a dead local socket is
  mis-classified as a provider refusal (`isConnectionRefusal`).

## Rules for this audit

- Read-only access to production: `$SCRATCH/prodsql.sh file.sql` (SELECT only) and
  `$SCRATCH/prodlogs.sh <service> <since> <pattern>`. Never write to the prod DB, never restart
  or deploy; the orchestrator deploys.
- Dev stack: `docker compose -f docker-compose.devdb.yml up -d` is already running (pgvector
  55432, redis 56379); env `backend/.env.hedwig-dev` (dead gateway URL so tests never hit
  llm-proxy or Tika); `node scripts/hedwig-migrate.mjs && node scripts/hedwig-seed.mjs`
  (user demo / hedwig-demo-password). Node 22: `export PATH=/opt/homebrew/opt/node@22/bin:$PATH`.
- Unit tests: `cd backend && npx vitest run src/hedwig/<area>`; frontend `cd frontend && npm test`.
  Integration tests share one DB and are order-sensitive; run only your own `*.it.test.js` files
  and reseed first. The orchestrator runs the full suites before deploy.
- Ownership by directory as in V2-BUILD.md. Shared files (`config.js`, `modules.js`, `hooks.js`,
  `worker.js`, `pipeline.js`) are append-only in your own marked block. Do not edit files owned by
  another area; write the request into your report instead.
- No new npm dependencies. AGPL. Keep upstream files untouched except `imapManager.js` (area E).
